1. Project Overview

Mini-Trello is a simple, modern, responsive single-page Kanban task-management application. A user can create tasks, view them grouped into three status columns (To Do, In Progress, Done), move tasks between columns with Next/Previous controls or drag-and-drop, and delete tasks. All data is stored in a real database and every action goes through a RESTful API, ensuring the board state persists across browser refreshes.

The project was developed to practice full-stack web engineering: a Vanilla JavaScript frontend, a Node.js + Express backend, and a NoSQL database (MongoDB), while applying Agile/Scrum execution across two one-week sprints.

Live Demo URL: https://trello-1-848v.onrender.com

2. Objectives

  • Build a task-management board with three status columns and full create/move/delete lifecycle flows.

  • Add per-task progress tracking with automatic synchronization on status change.

4. System Architecture

The system follows a decoupled single-page client-server model:

Browser (Single-Page App) | fetch() / XMLHttpRequest v Express REST API (server.js -- port 5000) | Mongoose ODM (parameterized queries) v MongoDB Database (tasks collection)

Detailed Architectural Flow

5. Database Design

The application persists records in a single tasks collection within MongoDB:

Field Type Description & Constraints
_id ObjectId (PK) Auto-generated unique task identifier.
title String Required, trimmed string representing the task summary.
description String Optional, defaults to empty string, trimmed.
status String (Enum) Restricted to todo, in_progress, or done.
progress Number Range: 0-100; auto-synced with status changes (todo=0, done=100).
createdBy String Required; name of the creator captured during first session.
createdAt DateTime Timestamp auto-generated via Mongoose timestamps: true.
updatedAt DateTime Timestamp automatically updated upon document mutation.

Schema Definition (Task.js)

const taskSchema = new mongoose.Schema( { title: { type: String, required: [true, "Title is required"], trim: true }, description: { type: String, default: "", trim: true }, status: { type: String, enum: ["todo", "in_progress", "done"], default: "todo" }, progress: { type: Number, min: 0, max: 100, default: 0 }, createdBy: { type: String, required: [true, "createdBy is required"], trim: true } }, { timestamps: true } );

6. UI Design & Theming

The interface implements an indigo-centered design system. CSS custom properties (design tokens) are declared centrally within frontend/style.css to ensure modular visual management:

  • Primary Accent: Indigo (#6366f1) paired with deep hover state (#4f46e5).
  • Canvas Background: Soft slate (#f8fafc) supporting elevated white card surfaces.
  • Column Palettes: Subtle tints -- To Do (#f1f5f0), In Progress (#e8f0fe), Done (#e6f7e6).
  • Status Indicators: Left border color accents matching status progression.
  • Glassmorphism Header: backdrop-filter: blur(12px) layered with semi-transparent alphas.
  • Typography: Google Fonts "Inter" (400, 500, 600, 700 weights).
  • Shadow Hierarchy: 4-tier elevation tokens (sm, md, lg, lift) providing depth separation.
  • Micro-Interactions: Modal popups, toast notifications, skeleton loaders, and card lifts.
  • Dynamic Theming: Toggle between light and slate-navy dark mode (#0f172a) with instant state restoration from localStorage before first paint.

11. Key Features (Detailed Breakdown)

  • Task Creation: Scale-in animated modal with field validation and client-side error handling.
  • Task Movement: Bi-directional column transitions with optimistic updates and failure rollback.
  • Native Drag & Drop: Native browser drag events triggering status update APIs on drop.
  • Progress Tracking: In-card progress slider for "In Progress" items, synchronized with header aggregate.
  • Safe Deletion: Dual-action confirmation dialog preventing accidental data loss.
  • Live Polling Engine: 5-second polling with signature hashing to eliminate unnecessary DOM redraws.
  • Personalized Avatars: Deterministic avatar color generation using creator name hash codes.
  • Dual Display Views: Switch between 3-column Kanban and numbered tabular listing.
  • Theme Persistence: Seamless theme toggling without flash of unstyled content (FOUC).
